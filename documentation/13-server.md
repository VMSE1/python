# Сервер курса: профили, онлайн-викторина, облако слов

Сайт остаётся на GitHub Pages. Серверу достаётся то, что статический сайт не умеет: хранить профили с паролями и передавать сообщения между телефонами в реальном времени.

## Что умеет
- **Профиль** (`account.html`): ник, фамилия и имя, группа, пароль. Прогресс (решённые и сданные задания, серия, сыгранные игры) хранится на сервере и подтягивается на любом устройстве. Вход через GitHub остаётся как был.
- **Онлайн-игра** (`live.html`): учитель создаёт комнату (викторина из `questions.js` или облако слов), показывает код из 4 цифр, ученики входят с телефонов. В викторине очки зависят от скорости верного ответа. Облако слов растёт на экране учителя в реальном времени, слова чистятся (`<b>` и подобное не исполняется).
- **Ученики на сервере** (`students.html`, только для учителя): таблица с группой, ФИО, ником, числом решённых заданий; выгрузка в CSV, смена пароля, удаление.

## Как это устроено
- `server/app.py`: один процесс на aiohttp (HTTP API и WebSocket `/ws`), база SQLite в `/var/lib/pycourse/data.sqlite`. Caddy принимает HTTPS и сам получает сертификат.
- Пароли хранятся как `scrypt` с отдельной солью; сам пароль не сохраняется и учителю не виден (учитель может только задать новый). После 6 неверных попыток вход блокируется на 5 минут. Лимиты на регистрацию, вход и подключения.
- Ключ учителя (`TEACHER_KEY` в `/etc/pycourse.env`) нужен, чтобы создавать комнаты и видеть список учеников. Его знает только учитель.
- Адрес сервера задан в `docs/config.js` и в строке `connect-src` (CSP) каждой страницы. Сменить: `python3 tools/set_server.py https://новый-адрес`.

## Установка на VPS
От root на чистом Debian/Ubuntu:

    curl -fsSL https://raw.githubusercontent.com/VMSE1/python/main/server/install.sh | bash

Скрипт ставит Python, Caddy, создаёт сервис `pycourse`, ежедневный бэкап базы (`/var/backups/pycourse`, 14 дней) и печатает адрес и ключ учителя. Адрес по умолчанию `https://<ip-через-дефисы>.sslip.io` (бесплатно, без регистрации домена). Свой домен: `... | bash -s -- course.example.com` (А-запись должна смотреть на IP). Порты 80 и 443 должны быть открыты. Обновление сервера: запустить ту же команду ещё раз.

## Эксплуатация
- Статус: `systemctl status pycourse`, логи: `journalctl -u pycourse -n 100`.
- Посмотреть базу: `sqlite3 /var/lib/pycourse/data.sqlite "select nick,fio,grp from users"`.
- Сменить ключ учителя: правка `/etc/pycourse.env`, затем `systemctl restart pycourse`.
- Если сервер упал, сайт работает как раньше; не работают только профили и онлайн-игра.

## Честные ограничения
- Прогресс на сервере присылает браузер ученика, поэтому он справочный. Настоящая проверка заданий остаётся за роботом на GitHub (см. `04-proverka-i-bezopasnost.md`).
- Школьная сеть может блокировать WebSocket или домен sslip.io. Проверь на уроке; запасной вариант: мобильный интернет или свой домен.
- Пароль ученика не восстанавливается: забыл, учитель задаёт новый.

## Тесты
`python3 -m unittest tests.test_server` (сервер без браузера) и `python3 tests/browser_tests.py online` (профиль, викторина, облако и кабинет учителя в браузере на настоящем сервере).
