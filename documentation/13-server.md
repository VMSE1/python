# Сервер курса: профили, онлайн-викторина, облако слов

Сайт остаётся на GitHub Pages. Серверу достаётся то, что статический сайт не умеет: хранить профили с паролями и передавать сообщения между телефонами в реальном времени.

## Что умеет
- **Профиль** (`account.html`): ник, фамилия и имя, группа, пароль. Прогресс (решённые и сданные задания, серия, сыгранные игры) хранится на сервере и подтягивается на любом устройстве. Вход через GitHub остаётся как был.
- **Онлайн-игра** (`live.html`): учитель создаёт комнату (викторина из `questions.js` или облако слов), показывает код из 4 цифр, ученики входят с телефонов. В викторине очки зависят от скорости верного ответа. Облако слов растёт на экране учителя в реальном времени, слова чистятся (`<b>` и подобное не исполняется).
- **Ученики на сервере** (`students.html`, только для учителя): таблица с группой, ФИО, ником, числом решённых заданий; выгрузка в CSV, смена пароля, удаление.

## Как это устроено
- `server/app.py`: один процесс на aiohttp (HTTP API и WebSocket `/ws`), база SQLite в `/var/lib/pycourse/data.sqlite`. Caddy принимает HTTPS и сам получает сертификат.
- Пароли хранятся как `scrypt` с отдельной солью; сам пароль не сохраняется и учителю не виден (учитель может только задать новый). После 6 неверных попыток вход блокируется на 5 минут. Лимиты на регистрацию, вход и подключения.
- Ключ учителя (`TEACHER_KEY` в `/etc/pycourse.env`) нужен, чтобы создавать комнаты и видеть список учеников. Его знает только учитель.
- Адрес сервера задан в `docs/config.js` и в строке `connect-src` (CSP) каждой страницы. Сменить: `python3 tools/set_server.py https://новый-адрес`.

## Установка на VPS
От root на чистом Debian/Ubuntu:

    curl -fsSL https://raw.githubusercontent.com/VMSE1/python/main/server/install.sh | bash

Скрипт ставит Python, Caddy, создаёт сервис `pycourse`, ежедневный бэкап базы (`/var/backups/pycourse`, 14 дней) и печатает адрес и ключ учителя. Адрес по умолчанию `https://<ip-через-дефисы>.sslip.io` (бесплатно, без регистрации домена). Свой домен: `... | bash -s -- course.example.com` (А-запись должна смотреть на IP). Порты 80 и 443 должны быть открыты. Обновление сервера: запустить ту же команду ещё раз.

## Эксплуатация
- Статус: `systemctl status pycourse`, логи: `journalctl -u pycourse -n 100`.
- Посмотреть базу: `sqlite3 /var/lib/pycourse/data.sqlite "select nick,fio,grp from users"`.
- Сменить ключ учителя: правка `/etc/pycourse.env`, затем `systemctl restart pycourse`.
- Если сервер упал, сайт работает как раньше; не работают только профили и онлайн-игра.

## Честные ограничения
- Прогресс на сервере присылает браузер ученика, поэтому он справочный. Настоящая проверка заданий остаётся за роботом на GitHub (см. `04-proverka-i-bezopasnost.md`).
- Школьная сеть может блокировать WebSocket или домен sslip.io. Проверь на уроке; запасной вариант: мобильный интернет или свой домен.
- Пароль ученика не восстанавливается: забыл, учитель задаёт новый.

## Тесты
`python3 -m unittest tests.test_server` (сервер без браузера) и `python3 tests/browser_tests.py online` (профиль, викторина, облако и кабинет учителя в браузере на настоящем сервере).

## Регистрация, вход и почта (с 22.10.2026)
- При первом заходе на любую страницу (кроме кабинета учителя) открывается окно `gate.js`: логин, пароль, почта (фамилия и группа по желанию). GitHub для учеников не нужен. Если сервер не отвечает 4 секунды, появляется кнопка «Продолжить без входа», чтобы сайт не закрылся из-за поломки сервера.
- **Вход:** после 3 неверных паролей блокировка 30 с, после 5 две минуты, с 7-й пять минут (потолок). Блок идёт по паре «ник + IP», плюс мягкий по самому нику (10 неудач с разных адресов дают 2 минуты). Счётчик забывается через 30 минут и сбрасывается верным паролем. Общий лимит по IP щедрый (300 входов и 80 регистраций в 10 минут и час), потому что класс сидит за одним школьным Wi-Fi.
- **Забыл пароль:** «Забыл пароль?» → логин или почта → на почту приходит 6-значный код на 30 минут (5 попыток, одноразовый) → новый пароль. Ответ сервера одинаков для существующего и несуществующего логина.
- **Почта сервера** (необязательно). В `/etc/pycourse.env` добавь: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USER=ящик@gmail.com`, `SMTP_PASS=пароль приложения` (Gmail: включить двухэтапную проверку и создать «Пароль приложения», 16 символов), `SMTP_FROM=ящик@gmail.com`, `TEACHER_EMAIL=куда слать уведомления`. Потом `systemctl restart pycourse`. Без почты код восстановления виден учителю в кабинете (вкладка «Пароли»), и он продиктует его ученику.
- **Защита от спама почтой:** не больше 6 писем за 10 минут и 20 в час на весь сервер, не больше 2 на один адрес за 10 минут (лимиты Gmail намного выше, у личного ящика 500 получателей в сутки). Учителю уведомления уходят не чаще раза в 10 минут одним письмом. Если лимит исчерпан, коды всё равно видны в кабинете.

## Сдача заданий на сервер (вместо GitHub)
`POST /api/submit`: ученик нажимает «Отправить учителю», сервер сам проверяет код в песочнице `check.py` (те же тесты, что и у робота), отмечает прогресс и сохраняет решение, метки защиты (бот, F12, правка из консоли, вставка) и результат. Учитель видит всё в кабинете (вход по ключу сервера): вкладка «Сдачи». Старый путь через GitHub-заявки остаётся только как скрытый «старый вход» в кабинете.

## Гонка по Python для всех
Вкладка «Игра» в кабинете. «Давайте поиграем!» у всех онлайн на 5 секунд показывает жёлто-оранжевый экран (человечки пляшут под солнцем), потом открывается `race.html`. Ученики заходят под своим логином, учитель жмёт «Старт», 5 задач по первым двум темам (`server/race.py`), код проверяет сервер, первые 3 финишировавших побеждают, гонка сама заканчивается на 5-м. Табло для проектора: `race.html?board=1`. Против подделки: код набирается на странице (метки `honest.js`), быстрее 14 символов в секунду отправить нельзя, решения по порядку, учитель может исключить игрока.

## Рулетка «три черепа»
Раз в 1–2 часа сервер выбирает одного случайного ученика из тех, кто сейчас на сайте (опрос `/api/play` раз в 4 секунды). У него появляется рулетка. Шанс трёх черепов `LUCKY_ODDS` (по умолчанию 0.25, в `/etc/pycourse.env`). Три черепа открывают игру «Скелет и бочки», попытка одна: победа даёт красную пятёрку («Позови преподавателя»), иначе «Ха-ха-ха» и оценка сгорает. Учитель видит итоги в кабинете и может запустить рулетку сразу (кнопка во вкладке «Игра»). Честно: игра идёт в браузере, поэтому сервер отклоняет победу быстрее 12 секунд и даёт один токен на попытку, но от опытного подделывателя это не защита. Для оценки смотри на экран с ником и временем.

## Секреты
Слово `skull` открывает «Убеги от скелета» (без оценки), `hop` — «Пикс-прыгун», `zap` — «Зап». `↑↑↓↓←→←→BA` открывает тренировку «Скелет и бочки». Семь быстрых нажатий на часы (за 4 секунды) показывают смеющегося скелета. В списки лидеров попадают `hop` (до 20000 очков) и `zap` (до 5000). После решённых заданий примерно в каждом третьем случае показывается подсказка (`EggHint` в `site.js`).


## Таблицы лидеров

| Запрос | Что делает |
|---|---|
| `POST /api/score` `{game, score}` | браузерная игра присылает результат; сервер хранит лучший на человека (таблица `scores`), нереальные значения молча игнорирует. Игры `race` и `boss` так не принимаются |
| `GET /api/leaderboards[?game=x]` | все таблицы (топ-10) или одна (топ-20), со своим местом. Нужен вход |

Игры и границы заданы в `BOARDS` в `app.py`. Гонка пишется в `race_submit`, босс по окончании боя (`boss_record`).

## Данные об учениках для кабинета

| Запрос | Что делает |
|---|---|
| `POST /api/quiz` `{lesson, score, total, ans}` | квиз присылает результат (только вошедшие; неверные ответы в `ans` как `[id вопроса, выбор]`). Таблица `quizzes`. Результат присылает браузер, это не защита от подделки |
| `GET /api/teacher/users` | все зарегистрированные: решено, сдано, лучший % по квизам каждого урока, число сдач, «сейчас на сайте», когда был |
| `GET /api/teacher/student?nick=` | полный прогресс одного ученика: задания и попытки, квизы с ошибками, лучшие результаты игр, события рулетки |

В БД добавлены таблица `quizzes`, индексы и колонка `users.seen` (последний раз на сайте, пишется раз в минуту). При удалении ученика стираются и его данные (сдачи, квизы, очки, рулетка). Страница `students.html`: нажми на строку ученика, чтобы увидеть всё.

## Шпион

`POST /api/spy/join`, `GET /api/spy/state`, `POST /api/spy/say|vote|guess`; управление из кабинета через `POST /api/teacher/play` с действиями `spy_announce`, `spy_start`, `spy_next`, `spy_cfg`, `spy_stop`, `spy_reset`, `spy_kick`, `spy_state`. Роль и чужие программы клиенту не отдаются до конца раунда.

## Босс-арена (`server/boss.py`)

| Запрос | Что делает |
|---|---|
| `POST /api/teacher/play` `{action: boss_announce / boss_start (hp_per) / boss_stop / boss_reset / boss_kick}` | управление из кабинета (нужен ключ учителя); `boss_reset` выключает игру |
| `GET /api/play` | общий опрос: поле `game` равно `boss` или `race`; арена имеет приоритет |
| `POST /api/boss/join` | войти в арену |
| `GET /api/boss/state?since=N` | состояние, рейтинг, события после номера N (для анимации), мой вопрос |
| `POST /api/boss/ask` `{lvl: easy/hard}` | выдать вопрос (варианты перемешаны, верный ответ не отдаётся) |
| `POST /api/boss/answer` `{a: номер}` | ответ; удар или лечение босса |

Банки вопросов по темам лежат в `boss_bank.py` (тема 0 = все). Константы в начале `boss.py`: `HP_PER_PLAYER`, `HP_MIN`, `DMG`, `HEAL_WRONG`, `STUN`, `LIMIT`, `REGEN_PER_SEC`, `BIG_HEAL`, `BIG_EVERY`. Запуск арены сбрасывает гонку, запуск гонки сбрасывает арену.


## Новое: респект, персонаж, игры по кнопке учителя
- `POST /api/teacher/play` `{action:"respect", nick?}`: экран «Респект» всем онлайн или одному.
- `{action:"apps_set", on:true|false}` / `{action:"apps_get"}`: открыть или убрать игры; `/api/play` отдаёт `apps.games`.
- `{action:"hearts"}`: кто ответил сердечком.
- `GET/POST /api/look`: персонаж ученика (нужен вход). `POST /api/heart`: ответное сердечко учителю.
- В базе: колонка `users.look`, таблица `kv(k,v)`. Обе создаются сами при запуске, ничего вручную не нужно. Чтобы это заработало на живом сервере, обнови его: `curl -fsSL https://raw.githubusercontent.com/VMSE1/python/main/server/install.sh | bash`.
