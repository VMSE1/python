# 4. Проверка кода и безопасность

## Два вида проверки

| | В браузере | На GitHub |
|---|---|---|
| Где идёт | У ученика, Pyodide в Web Worker | На одноразовой виртуальной машине GitHub Actions |
| Когда | «Проверить здесь» | После «Submit new issue» |
| Скорость | Секунды | Около минуты |
| Результат | Показывается ученику | Комментарий и метки в Issue, виден учителю |
| Нужен аккаунт | Нет | Да |

Правила проверки одни и те же: `task.json` у каждого задания (формат в [`CONTRIBUTING.md`](../CONTRIBUTING.md)). Сравнение не чувствительно к регистру и лишним пробелам.

## Как работает check.py

- `cases`: программа запускается с заданным вводом (`stdin`), в выводе должны быть фразы `must` и не должно быть `must_not`.
- `funcs`: вызывается функция с аргументами, результат сравнивается с `expect`.
- `files`: проверяет, что программа создала файл с нужным текстом.
- Команда локально: `python check.py --list`, `python check.py 2.4 --file мой.py`.

## Песочница check.py

Код ученика запускается отдельным процессом `python -I -c` с защитным хуком:

| Что запрещено или ограничено | Как |
|---|---|
| Сеть | `socket` заблокирован |
| Запуск программ | `subprocess`, `os.system`, `fork`, `kill`, `ctypes` заблокированы |
| Запись файлов | Только во временную рабочую папку |
| Чтение системных путей | `/proc`, `/home`, `/root`, `/run`, `/var`, `/mnt` и др. запрещены |
| Время | 5 секунд на выполнение |
| Память | 1 ГБ |
| Размер файла | 2 МБ |
| Дескрипторы | не более 64 |
| Вывод | Через временные файлы, не более 200 КБ |

Хук работает на уровне `sys.addaudithook`. Это защита «для школы», не военная изоляция: ученики в классе не атакуют серверы GitHub, а запуск идёт на одноразовой ВМ без секретов.

## Безопасность workflow

- Все actions закреплены на SHA коммита.
- У каждого job свои минимальные права (`issues: write` только там, где нужно).
- В shell попадает только номер задания, проверенный регулярным выражением; текст заявки идёт через файлы.
- Код ограничен 20 000 символами, комментарий робота 3000.
- Вывод очищается: убираются тройные кавычки, `@`-упоминания, HTML-комментарии.
- Одновременно на одну заявку работает одна проверка (`concurrency`).

## Безопасность сайта

| Угроза | Защита |
|---|---|
| Чужой скрипт на странице (XSS) | Весь текст из Issues и адресов экранируется (`esc()`), слова облака и ввод презентации выводятся через `textContent` |
| Подгрузка внешнего | `Content-Security-Policy` на каждой странице: запросы только на сам сайт и `api.github.com`, фреймы запрещены |
| Показ сайта во фрейме (clickjacking) | Страница скрывает себя, если открыта во фрейме |
| Формулы в Excel | Ячейки CSV, начинающиеся с `= + - @`, получают апостроф |
| Токен учителя | Токен без прав; хранится в `sessionStorage` (или 7 дней, если выбрано «запомнить»); уходит только на `api.github.com` |
| Накрутка облака слов | Один человек даёт слову один голос; до 5 слов в заявке |
| Метки заявок | Ставит робот, а не форма |

Подробная таблица: [`SECURITY.md`](../SECURITY.md).

## Защита от вставки готового кода

Цель: ученик набирает код сам, а не вставляет ответ от ИИ или из чата. Работает в `docs/honest.js` и на странице задания.

| Что | Как |
|---|---|
| Вставка | Ctrl+V, меню «Вставить», Shift+Insert и перетаскивание текста в редактор блокируются, ученик видит подсказку |
| Текст кусками | Если за одно действие появляется больше 25 символов (автодополнение ИИ, диктовка, расширения), оно блокируется |
| Учёт набора | Считаются набранные символы, попытки вставки, время набора; счётчики хранятся в `localStorage` и переживают перезагрузку |
| Эталонный текст | Страница хранит «эталон» набранного кода внутри замыкания, он меняется только настоящими (`isTrusted`) событиями набора. Проверка, отправка и хеш берут код из эталона, а не из поля |
| Обход через F12 | `ta.value = "..."` из консоли ничего не меняет; подмена через родной setter откатывается на следующем нажатии и на проверке; подделанные события ввода игнорируются; `execCommand` кусками упирается в предел 40 символов в секунду; код, подкинутый в `localStorage`, помечается. Каждая попытка увеличивает счётчик `e` |
| Тихая подмена | Любое изменение поля в обход набора фиксируется (`e`) и откатывается |
| Хеш кода | В заявку уходит служебное поле `v1;t=…;p=…;b=…;e=…;s=…;h=…`. Если код правили на GitHub, хеш не совпадёт |

Кабинет (вкладка «Заявки» и ⚠ в «Сводке») и робот BotBD показывают причины: «пытался вставить», «код изменён после сайта», «набрано 12 из 300 символов», «слишком быстрый набор», «отправлено не через сайт».

**Чего это не делает.** Тот, кто разберёт код страницы, всё равно обойдёт защиту: например, соберёт ссылку заявки руками с поддельным служебным полем. Защита в браузере принципиально не бывает полной. Она отсекает «вставил одну строку в консоли». Ученик может набрать чужой код руками, переписать его со второго экрана, подделать служебное поле в адресе заявки или править код в форме GitHub вместе с полем. Нельзя доказать, что код написан не нейросетью. Пометка нужна, чтобы выбрать, с кем поговорить. Надёжный способ: попросить объяснить свой код или изменить его на уроке.

Блокировка вставки мешает и честному переносу своего кода из другой программы. Если нужно, ученик набирает его заново или отправляет без сайта (такая заявка получит пометку «не через сайт»).

## Персональные данные

- Публичная форма просит **ник** и **номер группы**, но не фамилию и не имя.
- В Issues видны: ник, группа, GitHub-логин (он и так публичный), код, время.
- ФИО хранятся только у учителя: в его браузере (кабинет) и в приватном репозитории BotBD.
- Робот BotBD отказывается писать данные, если его репозиторий публичный.
- Вопросы согласия на обработку данных несовершеннолетних решай со школой; сайт собирает только то, что нужно для ведомости.

## Ограничения (честно)

- Кабинет учителя закрыт «для интерфейса», а не «для данных»: сайт статический, сдачи в публичных Issues видны всем.
- Задания и ответы видны в браузере: ученик может подогнать вывод. Проверяй сдачи выборочно.
- Pyodide выполняет код на устройстве самого ученика.
- GitHub API без токена даёт 60 запросов в час на IP. В школе с общим адресом страницы со списками могут временно не загрузиться: нажми «Обновить» позже.

## Защита от ботов (ввод кода)
Ученики могут попросить нейросеть написать скрипт (Selenium, Playwright, pyautogui), который сам «печатает» решение. Редактор (`docs/honest.js`) это замечает и блокируется: поле становится только для чтения, кнопки проверки и отправки отключаются, а на странице появляется красное сообщение «Ай-ай-ай! Похоже, код вводит бот». Блокировка держится 15 минут и не снимается обновлением страницы. В код сдачи попадает отметка `a=1`, и учитель видит причину «похоже на бота».

Что считается признаком бота: `navigator.webdriver`, «безголовый» браузер (HeadlessChrome), служебные переменные Selenium/Playwright/Puppeteer, слишком ровный ритм нажатий (разброс интервалов меньше 22% от среднего на 30 клавишах; у человека он заметно больше), много символов без нажатий клавиш на компьютере. Вставка, ввод скриптом и ввод слишком быстрее 40 символов в секунду блокировались и раньше.

Честно: это защита от «слепого» бота, которого нейросеть пишет за минуту. Опытный человек обойдёт любую проверку в браузере, поэтому главное остаётся прежним: настоящую проверку делает робот на GitHub, а учитель видит отметки и может попросить объяснить код. Если у тебя в BotBD разбор метаданных строгий, добавь ключ `a` в `bot/sync.py` (как `e`).

## F12 и инструменты разработчика
Сайт работает в браузере ученика, поэтому полностью закрыть F12 нельзя: это его компьютер. Что сделано, чтобы большинство ребят не лезло в код:
- На странице задания перехватываются F12, Ctrl+Shift+I/J/C и Ctrl+U, у редактора отключено контекстное меню.
- Сайт раз в секунду проверяет, открыты ли инструменты разработчика (остановка на `debugger` и проверка консоли). Если открыты, редактор блокируется, кнопка проверки отключается, показывается красное «Ай-ай-ай». После закрытия инструментов редактор разблокируется. В код сдачи попадает отметка `d=1`, учитель видит «открывал инструменты разработчика (F12)».
- Режим учителя (`localStorage.teacher`) этой проверке не подвержен, чтобы ты мог проверять сайт сам.

Что остаётся честным ограничением: ученик, который знает, как отключить точки остановки, закрепить окно отдельно или изменить код страницы, может обойти проверку. Поэтому правда о результате хранится не в браузере: решение проверяет робот на GitHub, а прогресс на сервере и в браузере только справочный. Дальше усиливать стоит серверную часть (журнал ввода на сервере), а не браузерную.
