# Безопасность сайта и проверки

## Что защищено и как

| Угроза | Что сделано |
|---|---|
| Чужой код в проверке на GitHub (`grade.yml`) | Код ученика идёт в отдельный процесс-песочницу (`check.py`): нет сети и запуска программ, запись только во временную папку, чтение системных путей запрещено, лимиты по времени (5 с), памяти (1 ГБ), размеру вывода (2 МБ). Сам запуск идёт на одноразовой виртуальной машине GitHub без секретов. Права токена: только `issues: write`. |
| Подмена и спам в ответе робота | Вывод программы очищается: убираются тройные кавычки, `@` (упоминания), HTML-комментарии. Лимит кода 20 000 символов, ответ до 3000 символов. |
| Внедрение через заголовок/текст Issue | В shell попадает только номер задания (проверяется регуляркой `\d+\.\d+`). Остальное идёт через файлы, не через `${{ }}`. |
| Подмена действий в workflow | Все actions закреплены на конкретный коммит (SHA), а не на изменяемый тег. |
| XSS (чужой скрипт на сайте) | Весь текст из Issue и из ссылок экранируется. Заголовок `Content-Security-Policy` на каждой странице: запросы разрешены только на сам сайт и `api.github.com`, чужие скрипты и фреймы запрещены. |
| Утечка токена учителя | Токен без прав (нужен только чтобы GitHub подтвердил владельца). Хранится в `sessionStorage` (закрыл вкладку — стёрся). Если выбрано «запомнить», живёт 7 дней. Уходит только на `api.github.com`. |
| Формулы в Excel (CSV-инъекция) | Ячейки, начинающиеся на `= + - @`, получают апостроф. |
| Накрутка и мусор в облаке слов | Один человек даёт слову один голос, до 5 слов в заявке, слова выводятся как текст (`textContent`), лишнее скрывается меткой `скрыто`. Метку `облако` ставит робот. |
| Вставка готового кода (в том числе от ИИ) | Поле кода не принимает вставку (Ctrl+V, меню, перетаскивание) и текст «кусками» больше 25 символов. Сайт считает набранные символы и кладёт в заявку служебное поле с хешем кода. Кабинет и робот помечают вставку, правки на GitHub и слишком быстрый набор. Это сдерживание, а не гарантия. |
| Clickjacking | Сайт, открытый во фрейме чужой страницы, скрывает себя. |

## Чего защита НЕ делает (честно)

- **Кабинет учителя закрыт «для интерфейса», а не «для данных».** Сайт статический, секретов в нём нет. Сдачи ребят это публичные Issues (поэтому только ники, не фамилии). Настоящие ФИО хранятся **только в браузере учителя** (`localStorage`) и в сам сайт и на GitHub не уходят. Выгрузка собирается в браузере и никуда не отправляется.
- Если репозиторий публичный, любой может прочитать Issues. Для закрытых данных нужен приватный репозиторий (платный план GitHub Pages) или свой сервер.
- Песочница это защита «для школы», а не военная изоляция. Задания и ожидаемые ответы видны в браузере, поэтому ученик может подогнать вывод. Проверяй сдачи выборочно.
- Pyodide (проверка в браузере) выполняет код в браузере самого ученика, на его же устройстве.

## Как проверить

```bash
python -m unittest tests.test_sandbox -v          # атаки на песочницу
pip install playwright && playwright install chromium
python tests/browser_tests.py                     # дымовые, функциональные, безопасность, производительность, нагрузка
```

Нашёл уязвимость? Напиши владельцу репозитория (не публикуй в Issue).

## Персональные данные
Публичная форма не собирает ФИО. Ник, группа и GitHub-логин видны в Issues. ФИО хранятся только в приватном репозитории BotBD; робот отказывается писать данные, если он публичный.
